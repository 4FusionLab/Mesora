# Выбор лицензии для новых продуктов 4FusionLab

[English](LICENSING.md)

**Шаблон репозитория не выбирает лицензию для создаваемого аддона.** Добавьте файл `LICENSE` после осознанного решения для продукта, желательно до принятия внешних изменений или выпуска исполняемых файлов.

| Сценарий | Типичный выбор | Последствия |
| --- | --- | --- |
| Аддон, развиваемый сообществом, с взаимным предоставлением исходников | GPL-3.0-only | Распространение производных работ, как правило, остаётся под условиями GPL. Проверьте совместимость нативных и сторонних библиотек. |
| Повторно используемый компонент с разрешительной открытой лицензией | MIT или Apache-2.0 | Проще использовать в других продуктах; публикация изменений может не требоваться. |
| Платный аддон с закрытым исходным кодом | Проприетарные условия / EULA | Храните исходный код в закрытом репозитории; определите права использования, обновления и лицензии сторонних зависимостей. |
| Открытый исходный код и платные услуги | Специальная или двойная лицензия после юридической проверки | Уточните, какие части открыты, платны или подчиняются другим условиям. |

Не считайте публичный репозиторий GitHub автоматически лицензированным как открытое ПО. Не копируйте по ошибке лицензию GPL и исходный код существующего GPL-аддона в проприетарный проект без оценки обязательств. Сгенерированный стартовый код независим от реализаций других продуктов 4FusionLab.

Лицензирование не зависит от GitVersion, CI и автоматизации релизов. Рассматривайте его как отдельное продуктовое и юридическое решение; не меняйте лицензию уже выпущенных проектов без разрешения и анализа совместимости.
