# Managed observer и восстановление нативной приёмки

Рабочая заметка от 2026-11-13. Нативные результаты сообщил root — единственный
владелец Fusion в этой приёмке; автор заметки не обращался к нативной сессии.

## Подтверждённые границы доказательств

- Observer, запущенный штатным Script Manager, получил собственный
  `customEvent.callback`. Это подтверждает доставку его callback, в отличие от
  предыдущего наблюдателя, зарегистрированного из MCP script.
- В сообщённой трассе UI Save As присутствуют `PLM360SaveAs`, `documentSaving`
  и `documentSaved` с нулём групп; завершение save не восстановило графику.
  Это не заменяет визуальную проверку повторного открытия без Mesora.
- Следующий этап прерван зависанием Fusion при обращении к дереву accessibility
  окна Parameters. В сообщённом sample основной поток проходит через
  `_AXXMIGCopyHierarchy` и `QMacAccessibilityElement::accessibilitySelectedChildren`.
  Стек не содержит Python/Mesora. Это свидетельство места остановки потока;
  первопричина и отсутствие иных факторов этим sample не установлены.
- CUA и MCP перестали отвечать. Нативные сценарии, прерванные этим состоянием,
  остаются незавершёнными. Несохранённый пользовательский документ нельзя
  закрывать или принудительно завершать Fusion ради продолжения приёмки.

## После восстановления отзывчивости

1. Сначала убедиться, что пользовательская работа сохранена доступным штатным
   способом. Не выполнять массовые закрытия документов.
2. Для Parameters использовать снимок экрана и ограниченные клавиатурные
   действия. Не запрашивать полное AX-дерево Qt Parameters, особенно после
   раскрытия дерева параметров. Каждое изменение подтверждать изображением или
   узким чтением Fusion API на разрешённом основном потоке.
3. Если observer ещё работает, остановить **MesoraAcceptanceObserver** через
   Script Manager. Проверить `isRunning=False` и финальную запись
   `observer.stopped` с `remaining_handlers=0`; `observer.detach_failed` означает,
   что очистка не подтверждена. Остановка не должна менять CAD.
4. Если Fusion уже перезапущена, прежние callback не живут в новой сессии.
   Сохранить прежний JSONL как доказательство и начать новую сессию observer.

## Повторяемый запуск observer

Из корня checkout выполнить:

```sh
python3 scripts/prepare_native_observer.py
```

Генератор создаёт исключённый из Git и продукта каталог
`dist/native-acceptance/MesoraAcceptanceObserver`. Он копирует актуальный
`scripts/native_acceptance_observer.py` как относительный подмодуль и создаёт
manifest и entrypoint. В исходниках генератора нет абсолютных пользовательских
путей. Существующий `events.jsonl` сохраняется, новые сессии дописываются.
Не регенерировать файлы работающего observer: сначала штатно остановить его.

Через `Application.scripts.itemByPath(folder)` получить зарегистрированный
observer; только при его отсутствии использовать `addExisting(folder)`.
Для observer оставить `isRunOnStartup=False` и вызвать `run(False)`, затем вернуть
управление Fusion. Для Mesora сохранить пользовательский `Run on Startup=True`.

Проверить новую запись `customEvent.callback`, прежде чем интерпретировать
отсутствие других событий. `observer.started`, `customEvent.queued` и
`isRunning=True` сами по себе доставку callback не доказывают.

Не вызывать `start()` наблюдателя через импорт из MCP script и не заменять
штатный запуск Mesora вызовом `exec` её исходника. После managed stop/run проверить
фактическое открытие команды Mesora; затем выполнять save/reopen/restart и
отдельно визуально проверять отсутствие размеров при остановленной Mesora.
