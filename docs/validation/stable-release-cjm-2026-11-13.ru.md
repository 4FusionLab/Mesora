# Mesora: CJM и приёмка стабильного релиза

Дата: 13.11.2026. Рабочий документ приёмки; не свидетельство завершённой CAD-проверки.

## Продуктовая цель

Конструктор один раз создаёт информационные размеры и использует их при изменении, сохранении и передаче модели в Drawing. Он может убрать визуальный шум без потери измерений и вернуться к работе после закрытия Fusion. Размеры соответствуют актуальной геометрии; недоступная ссылка явно обозначена, старое число не выдаётся за актуальное. Mesora не создаёт повторные сохранения и не оставляет неуправляемую графику в файле.

## Правила доказательств

Нативные проверки выполняются одним владельцем Fusion на отдельных синтетических документах. Пользовательские модели не используются. Для каждого прогона фиксировать ревизию исходников, версию Fusion и ОС, имя фикстуры, операции, значения до/после, фактический результат и ссылку на снимок/лог. Повторная проверка после исправления относится к новой ревизии; старый PASS не переносится автоматически. `customGraphicsGroups.count == 0` не доказывает отсутствие видимых orphan graphics: требуются снимки после reopen/restart с отключённым Mesora.

Обозначения: **AUTO PASS (baseline)** — воспроизведено офлайн в начале этой работы; **переданный macOS PASS** — доказательства предыдущего прогона в [отчёте Drawing](drawing-visibility-2026-11-13.ru.md), не новая приёмка; **PENDING** — необходим реальный прогон. Windows Fusion оценивается отдельно от Windows CI.

## Повторная офлайн-проверка после доработок

13.11.2026 на текущем рабочем коде: **97 tests, OK**. Добавлены проверки сохранения всех типов и настроек runtime schema, invalidation геометрии и placement dependencies, восстановления строки с недоступной ссылкой, отмены save при ошибке cleanup через `isOperationCancelled`, объединения событий, исключения Drawing/редактора и отсутствия перерисовки при неизменившемся snapshot после Save. Undo последней удалённой строки проверен через реальный обработчик событий и `State.load`; Undo создания до пустого набора — через реальный `State.refresh` и удаление graphics group. Это офлайн-объекты событий, а не нативный transaction/event-order gate.

D01/D02/D03 имеют реализацию и офлайн-регрессии; закрытие для stable требует указанных нативных сценариев на финальном коде. Новый S19 обязателен по прямому уточнению пользователя: проект должен нормально использоваться без Mesora.

## Блокирующее нативное доказательство S19

Владелец Fusion (root) 13.11.2026 подтвердил: использование геометрии без Mesora возможно, но старые аннотации остаются видимыми после редактирования и повторного открытия. При радиусе 2.5 cm окружность должна иметь длину около 157.1 mm; виден старый label 125.7 mm. При этом `customGraphicsGroups.count == 0`, так что удалить этот label обычным управлением группами невозможно. S19 **FAIL**, доверие к информационным размерам нарушено; stable release заблокирован до устранения и повторной визуальной приёмки. Это переданное свидетельство root, субагент не управлял Fusion.

## Проверка обработчиков и cleanup после обнаружения orphan

На последнем рабочем коде **103 offline tests, OK**. Дополнительные регрессии проверяют: при отказе удаления старой графики новые definitions не записываются; не удалённые staged graphics сохраняют управляемые ссылки для повторной очистки; exception при staged cleanup также сохраняет ссылку; ошибка unregister custom event не мешает удалению UI и handlers, состояние с неочищенной графикой остаётся доступным для повторной очистки.

Root отдельно проверил нативные операции с **явным программным вызовом** обработчика `DocumentEvent('saving')` перед API save: после reopen orphan отсутствовал, definitions восстановились. Прямой нативный вызов обработчика auto-update также обновил результат. Это подтверждает локальные операции обработчиков на реальной геометрии, но **не** доказывает, что обычный пользовательский Save/Save As/команда редактирования доставляет нужные события в нужном порядке. Эти результаты не закрывают S19 FAIL и end-to-end gates сохранения/перезапуска. Для закрытия нужны действия через штатный UI Fusion, без ручного вызова обработчиков, с теми же визуальными проверками.
