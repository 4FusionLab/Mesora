# Mesora: CJM и приёмка стабильного релиза

Дата: 13.11.2026. Рабочий документ приёмки; не свидетельство завершённой CAD-проверки.

## Продуктовая цель

Конструктор один раз создаёт информационные размеры и использует их при изменении, сохранении и передаче модели в Drawing. По уточнению пользователя графика существует только при работающей Mesora; в проекте сохраняются определения измерений и настройки, а не отображаемые аннотации. Он может убрать визуальный шум без потери измерений и вернуться к работе после закрытия Fusion. Размеры соответствуют актуальной геометрии; недоступная ссылка явно обозначена, старое число не выдаётся за актуальное. Mesora не создаёт повторные сохранения и не оставляет неуправляемую графику в файле.

## Правила доказательств

Нативные проверки выполняются одним владельцем Fusion на отдельных синтетических документах. Пользовательские модели не используются. Для каждого прогона фиксировать ревизию исходников, версию Fusion и ОС, имя фикстуры, операции, значения до/после, фактический результат и ссылку на снимок/лог. Повторная проверка после исправления относится к новой ревизии; старый PASS не переносится автоматически. `customGraphicsGroups.count == 0` не доказывает отсутствие видимых orphan graphics: требуются снимки после reopen/restart с отключённым Mesora.

Обозначения: **AUTO PASS (baseline)** — воспроизведено офлайн в начале этой работы; **переданный macOS PASS** — доказательства предыдущего прогона в [отчёте Drawing](drawing-visibility-2026-11-13.ru.md), не новая приёмка; **PENDING** — необходим реальный прогон. Windows Fusion оценивается отдельно от Windows CI.

## Историческое наблюдение S19 в раннем harness

Владелец Fusion (root) 13.11.2026 подтвердил: использование геометрии без Mesora возможно, но старые аннотации остаются видимыми после редактирования и повторного открытия. При радиусе 2.5 cm окружность должна иметь длину около 157.1 mm; виден старый label 125.7 mm. При этом `customGraphicsGroups.count == 0`, так что удалить этот label обычным управлением группами невозможно. В том прогоне S19 **FAIL**. Это историческое наблюдение результата раннего harness; оно не доказывает причину и не заменяет повторную проверку штатно запущенного аддина. ## Проверка обработчиков и cleanup после обнаружения orphan

На последнем рабочем коде **103 offline tests, OK**. Дополнительные регрессии проверяют: при отказе удаления старой графики новые definitions не записываются; не удалённые staged graphics сохраняют управляемые ссылки для повторной очистки; exception при staged cleanup также сохраняет ссылку; ошибка unregister custom event не мешает удалению UI и handlers, состояние с неочищенной графикой остаётся доступным для повторной очистки.

Root отдельно проверил нативные операции с **явным программным вызовом** обработчика `DocumentEvent('saving')` перед API save: после reopen orphan отсутствовал, definitions восстановились. Прямой нативный вызов обработчика auto-update также обновил результат. Это подтверждает локальные операции обработчиков на реальной геометрии, но **не** доказывает, что обычный пользовательский Save/Save As/команда редактирования доставляет нужные события в нужном порядке. Эти прямые вызовы сами по себе не закрывают S19 и end-to-end gates сохранения/перезапуска. Для закрытия нужны действия через штатный UI Fusion, без ручного вызова обработчиков, с теми же визуальными проверками.

## Уточнённый контракт при отсутствии Mesora

Пользователь подтвердил: без Mesora размеры **не должны отображаться**. Проект содержит только definitions (тип, ссылки на геометрию, offsets и видимость); отображаемую графику строит работающий аддин. После изменения модели без Mesora и последующего запуска аддина значения вычисляются заново, видимые размеры отрисовываются автоматически. Не требуется и недопустимо оставлять «замороженные» размеры для просмотра без аддина. Поэтому ранее наблюдавшийся старый label — нарушение именно отсутствия аннотаций, независимо от значения label.

Причина прошлых orphan-наблюдений на уровне конкретного дефекта Autodesk или жизненного цикла обработчиков **не установлена**. Root проверяет штатный запуск/остановку через менеджер Scripts and Add-ins. Прямой `exec` модуля и прямые вызовы обработчиков нельзя считать доказательством нормального жизненного цикла аддина. Предыдущие фактические снимки остаются доказательством результата своего прогона; переносить их на новую установленную ревизию без повторения нельзя.

| L07 | Без Mesora открыть, изменить, сохранить, переоткрыть; затем штатно запустить Mesora | До запуска нет аннотаций; после запуска только актуальные значения, сохранены row/global visibility | Сохранённые определения не содержат measured value; fingerprint первоначально вычислен для загруженного состояния, не подавляет initial render |

Эти offline-проверки следует добавлять вокруг внешнего lifecycle и observable state, а не проверять конкретное число внутренних вызовов как самоцель. Реальная доставка Fusion events, время сохранения графики и отсутствие orphan остаются нативными gates.

## Минимальный сборщик доказательств для нативного прогона

Помощник должен **наблюдать** штатные события, а не вызывать `DocumentEvent.notify`, `State.refresh` или `Execute.notify` вместо действий пользователя. Допустимы read-only снимки состояния, временные observer handlers и запись JSONL локально вне публичного пакета. Он не должен изменять attributes, геометрию, признаки modified или CAD-архивы. Для тестовой геометрии сохраняются независимые ожидаемые величины (например, длина окружности `2*pi*r`) и Fusion Inspect.

Для каждого события нужны: sequence, monotonic timestamp, имя штатного события, process/session/addin-instance ID, ревизия пакета и версия Fusion, синтетическое имя документа, активный workspace/command, `isModified`, API graphics count, runtime managed count и removed-for-save/editor flags, безопасный digest definitions (без entity tokens/доступных URL). Снимки: перед Save; после завершения Save; после stop; reopen с отключённой Mesora; после изменения и второго reopen; после штатного запуска Mesora. Счётчик API не заменяет снимок. Лог и screenshots связываются одним case/run ID.

Проверка evidence должна отвечать на продуктовые вопросы: получен ли Saving обычным сохранением; исчезли ли managed graphics до записи; был ли Saved; не начался ли второй Save; исчезли ли **визуально** все аннотации без Mesora; сохранилась ли геометрия и definitions; появились ли после запуска актуальные значения. Отсутствующее событие или снимок означает INCONCLUSIVE, не PASS и не доказанную причину дефекта. Сборщик не должен содержать пользовательские модели, credentials, tokens или приватные пути в коммитах.

## Штатный нативный прогон f090654: Save и повторное открытие без аддина

Новые переданные root доказательства получены со штатно управляемой Mesora (Scripts and Add-ins), а не прямым `exec` продукта:

1. Открытие безопасной синтетической фикстуры v2 автоматически загрузило два определения и отрисовало одну группу: m1 скрыт.

Внешние observer handlers, импортированные из MCP-контекста и не получившие callbacks, **не дают** evidence product event lifecycle. ## Исправление оценки S07: Undo graphics FAIL, D06

Субагент прочитал реальный локальный observer trace `dist/native-acceptance/MesoraAcceptanceObserver/events.jsonl` (counters26–49). После OK hide-both (29–31) и runtime, и design имеют 0 групп.
