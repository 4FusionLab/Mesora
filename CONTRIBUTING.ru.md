# Участие в разработке аддонов 4FusionLab

[English](CONTRIBUTING.md)

Добро пожаловать! Изменения должны быть целенаправленными, проверяемыми и безопасными для запуска в Autodesk Fusion.

- Обсуждайте несовместимые изменения CAD-поведения и интерфейса до реализации.
- Предпочитайте один небольшой PR на каждое логическое изменение и Conventional Commits (`feat:`, `fix:`, `perf:`, `docs:`, `refactor:`).
- Держите предметную логику независимой от среды Autodesk и покрывайте её значимыми автономными тестами.
- Не добавляйте в репозиторий модели клиентов, учётные данные, ключи и абсолютные пути пользователей.
- Локально запускайте `python -m unittest discover -s tests -v` и `python scripts/build.py --version 0.1.0`; CI проверяет три операционные системы.
- Различайте результаты автономных тестов и фактическую приёмку CAD-сценариев в Fusion.
- При изменении пользовательского поведения обновляйте обе языковые версии README.
- Изменения исполняемых компонентов, объединённые с `main`, публикуются автоматически только после успешного CI; не создавайте теги релизов вручную.

Полный порядок работы описан в [руководстве разработчика](docs/DEVELOPMENT.ru.md).
