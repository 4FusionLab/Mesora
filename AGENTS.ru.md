# Правила разработки аддонов 4FusionLab для Fusion

[English](AGENTS.md)

Сначала прочитайте [общие инженерные правила 4FusionLab](https://github.com/4FusionLab/.github/blob/main/AGENTS.md) и [платформу релизов](https://github.com/4FusionLab/.github/blob/main/RELEASE_PLATFORM.md).

## Порядок работы

- Это аддон Autodesk Fusion на Python. Начальный пакет — `FusionAddin/`; инициализатор заменяет его имя и создаёт стабильные идентификаторы.
- Обсуждайте требования и планы на русском. Для команд, элементов управления и диагностики Fusion и стабильных имён API используйте понятный английский. Поддерживайте отдельные английский и русский README.
- Считайте официальную документацию Autodesk Fusion API источником истины. Никогда не выдумывайте символы SDK; успешный автономный CI сам по себе не означает приёмку CAD.
- Расчёты и предметные правила размещайте в `FusionAddin/core.py` или модулях, которые **не импортируют adsk**. Взаимодействия с Fusion API относятся к адаптерам, обработчикам событий и командам, выполняемым в разрешённом контексте Fusion.
- Делайте команды безопасными: проверяйте активный документ, объекты, единицы, параметры и состояние таймлайна; используйте нативный предпросмотр, где применимо. Никогда не изменяйте CAD-данные пользователя в тестах или без явного действия командой.
- Сохраняйте экземпляры обработчиков событий на время работы; в `stop(context)` отсоединяйте элементы интерфейса и определения команд. После начального создания сохраняйте идентификаторы стабильными. Избегайте глобального состояния, связанного с устаревшими документами.
- Добавляйте значимые модульные и автономные интеграционные тесты. Когда это важно, отдельно проверяйте реальные сценарии Fusion на Windows/macOS; сообщайте, что фактически проверено, а что нет.

## Версии и публикация

- `python scripts/init_addin.py --name NewAddin` выполняется **один раз**; никогда не создавайте заново UUID манифеста или ID команд существующего продукта.
- Для версии используются GitVersion.Tool **6.8.2**, Conventional Commits и закреплённые общие Actions. Прямой push или объединение PR в `main` запускает релиз **только** для поставляемых путей из `.github/release-paths.txt`.
- До публикации должны пройти все проверки. Изменения документации, тестов и CI не публикуют новый релиз. Не создавайте теги вручную, не перезаписывайте опубликованные ZIP и не перемещайте существующие теги.
- Только задание публикации имеет `contents: write`. Версия ZIP, встроенного манифеста, контрольные суммы и заметки релиза должны совпадать. ZIP должен устанавливаться как папка Fusion Add-in.
- Не коммитьте учётные данные, частные CAD-файлы, ключи подписи, созданные платформой артефакты и пользовательские пути. Перед публичным распространением проверьте лицензирование репозитория.

## Команды

- Автономные тесты: `python -m unittest discover -s tests -v`.
- Валидатор проекта: `python scripts/check_project.py`.
- ZIP продукта: `python scripts/build.py --version 0.1.0`.
- Контрольный список ручной CAD-приёмки: `docs/DEVELOPMENT.md`.
